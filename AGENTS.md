# AGENTS.md

- Agent-first project: act autonomously, including commits and pushes. Block on a human only for expensive or hard-to-undo operations.
- Track all work in GitHub issues; reference the issue in commits.
- Don't use harness memory systems; record durable knowledge here.
- Every instruction here must earn its tokens: cut prose that doesn't change agent behavior.
- No status disclaimers in docs ("currently", "early days", "coming next"); they go stale. Track status in issues.
- AGENTS.md is not README.md: project descriptions go in README.md; only agent instructions go here.
- Every source file starts with SPDX headers: `SPDX-FileCopyrightText: 2026 Maksym Motorny` (current year for new files) and `SPDX-License-Identifier: BSD-3-Clause`, in the file's comment syntax.
- Naming: product crate `volya-engine`, role sub-crates `volya-engine-<role>` in `crates/`, platform packages `platforms/<platform>` with crate `volya-engine-<platform>`, tools `tools/<tool>` with crate `volya-engine-<tool>` (except `xtask`, by Cargo convention) (see docs/architecture.md). Create a crate only when its code exists.
- Never add URL query parameters (`?…`) without the user's explicit approval.
- Follow docs/architecture.md; update it when a decision changes.
- No shell scripts: project tasks live in `tools/xtask` (`cargo xtask <task>`).
- Live at head: run `cargo xtask update` when starting a chunk of work; fix what it breaks rather than pinning.
- Run `cargo xtask check` (fast static checks) before every push; it must pass.
- Iteration speed first: before reporting done, run only high-ROI tests directly related to the change. End-to-end and multi-device tests (`cargo xtask e2e`) run only on demand; never block normal interaction on them.
- Avoid GitHub CI whenever possible (cost); all testing runs locally.
- Work by the priorities in docs/roadmap.md; record roadmap decisions there, not here.
- Agents test desktop Chrome and Mobile Safari in the iOS Simulator; the user checks only Chrome on iOS on the reference device. Never ask the user to check anything else.
- Web build must keep functional parity between mobile and desktop browsers; every feature ships with both input paths (touch and keyboard/mouse/gamepad) and is tested on both.
- Dependencies must be permissively licensed (no copyleft, including LGPL/MPL).
- Never use or derive from leaked X-Ray source or its forks (e.g. OpenXRay).
- Never commit game assets, including test fixtures; tests needing game data skip when it's absent.
